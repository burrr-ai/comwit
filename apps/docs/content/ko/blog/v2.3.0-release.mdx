## 첫 스냅샷 전에 서버 데이터를 초기화합니다

v2.3.0부터 `create()`가 만든 훅에 `useDomain.hydrate(entries)`가 추가됩니다. 작은 Client Component 라우트 어댑터가 실제 UI의 첫 `useSyncExternalStore` 스냅샷 읽기 전에 완료된 Server Component 데이터를 초기화합니다.

```tsx
// Server Component
const initialPost = await serverApi.findBySlug(slug)
return <BlogRoute slug={slug} initialPost={initialPost} />

// Client route adapter
function BlogRoute({ slug, initialPost }: Props) {
  useBlogSocial.hydrate({
    post: { arg: slug, data: initialPost },
  })
  return <BlogArticle />
}

// Actual UI
function BlogArticle() {
  const post = useBlogSocial((state) => state.post.data)
  return post ? <Article post={post} /> : null
}
```

완료된 서버 값을 받는 컴포넌트는 라우트 어댑터 하나뿐입니다. 비즈니스 UI는 일반 도메인 훅을 계속 읽으므로 데이터 prop을 중복해서 전달하지 않습니다.

<a id="typed-complete-query-entries"></a>

## 타입이 지정된 완전한 쿼리 항목

`hydrate()`는 모델에서 허용 필드와 각 `arg`, `data` 타입을 추론합니다. 내부에서 최신 시각을 기록하고 직렬화된 인자를 활성 키로 선택하며, 로딩과 fetching이 꺼진 완전한 성공 항목을 만듭니다. `null`과 `undefined` 입력은 아무 작업도 하지 않습니다.

`query()`, `query.infinite()`, `local.query()`, `local.infinite()`를 지원합니다. 복원된 로컬 쿼리는 기준 엔티티를 조정하고 커밋 후 IndexedDB에 저장합니다. 실시간 및 독립 `local()` 리소스는 지원 대상에서 제외됩니다.

같은 Provider, 필드, 키, 데이터의 복원은 여러 번 실행해도 결과가 같습니다. 아직 읽지 않은 새 항목은 첫 스냅샷 전에 초기화할 수 있습니다. 이미 관찰된 항목의 갱신은 요청한 렌더가 커밋될 때까지 기다리므로, 취소된 라우트 전환이 현재 화면 상태를 덮어쓰지 않습니다. 복원된 값은 같은 키의 이전 진행 중 요청도 무효화합니다.

<a id="why-silent-was-not-enough"></a>

## `silent()`만으로 부족했던 이유

`silent()`는 구독 콜백을 억제해도 React의 외부 저장소 스냅샷 검사는 막지 못했습니다. `useSyncExternalStore`가 읽은 뒤 모델을 변경하면 Next.js Cache Components와 부분 사전 렌더링 환경에서 React 19가 커밋 전 렌더를 반복해서 버리고 재시도할 수 있었습니다.

이제 `silent()`는 사용이 권장되지 않으며 렌더 중 데이터 복원에 사용하면 안 됩니다. 새 복원 경로는 렌더 중 액션, 공개 프록시, `.set()`, `silent()`를 호출하지 않습니다.

<a id="query-loading-and-experimental-suspense"></a>

## 쿼리 로딩과 실험적 Suspense

셀렉터 `.load(arg)`는 계속 기본 클라이언트 조회 경로이며 중단 없이 커밋 후 작업을 시작합니다. `.suspend(arg)`는 서버와 브라우저에서 모두 동작하는 HTTP 쿼리 함수를 위한 실험적 렌더 중 조회 경로로 유지됩니다. Promise나 초기 데이터 재정의는 받지 않습니다. Next.js Server Functions는 Server Component에서 실행한 뒤 완료된 값을 `hydrate()`로 전달해야 합니다.

선언 수준 `suspense` 옵션과 `Query.Suspense*` 별칭은 사용 중단된 호환 API로 남습니다.
