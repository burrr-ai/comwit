> **안전성 안내:** 이 과거 릴리스에 나오는 렌더 중 `silent(() => resource.set(...))` 초기화는 더 이상 권장하지 않습니다. 구독 콜백을 억제해도 React는 외부 저장소 스냅샷 변경을 감지합니다. SSR 쿼리 데이터에는 셀렉터 `.suspend(arg)`를 사용하세요.

<a id="query-arguments-now-belong-in-the-selector"></a>

## 쿼리 인자를 셀렉터에서 선언할 수 있습니다

기존처럼 액션에서 명령형으로 쿼리를 불러올 수 있습니다. v2.1.0은 마운트된 화면이 소유하는 요청을 위해 수명 주기가 관리되는 두 번째 경로를 추가합니다.

```tsx
const products = useProduct((state) => state.products.load({ page, filter }))
```

`.load()` 인자는 모델의 `Query<Data, Arg>` 선언에서 추론됩니다. 인자가 없는 쿼리는 `load()`를 호출하고, 인자가 있는 쿼리는 정확한 `Arg` 타입을 전달합니다.

호출 자체가 기능을 켜는 선택입니다. `.load(...)` 없이 `state.products`를 선택하면 수동 읽기로 남으며 요청을 시작하지 않습니다.

<a id="why-add-it"></a>

## 왜 추가했나요?

이전에는 보통 컴포넌트의 `useEffect`에서 액션을 시작했습니다.

```tsx
const products = useProduct((state) => state.products)

useEffect(() => {
  actions.loadProducts({ page, filter })
}, [page, filter])
```

이펙트가 실행되기 전 쿼리는 빈 `initialData`, `isLoading: false`인 초기 상태였습니다. 로딩/빈 상태/콘텐츠를 나누는 화면은 스켈레톤으로 전환하기 전에 빈 상태를 잠깐 표시할 수 있었습니다.

셀렉터 `.load(arg)`를 사용하면 렌더 중에 키를 알 수 있습니다. 첫 렌더부터 선택한 리소스가 로딩을 인식하고, React 커밋 후 요청을 시작합니다.

<a id="lifecycle-and-cache-behavior"></a>

## 수명 주기와 캐시 동작

- 직렬화된 인자가 같은 일반 리렌더는 요청을 다시 시작하지 않습니다.
- 인자가 바뀌면 새 캐시 키를 선택하고 불러옵니다.
- 같은 리소스와 키를 동시에 불러오는 셀렉터는 진행 중인 요청을 공유합니다.
- 기존 인자별 캐시, `staleTime`, `gcTime`, `placeholderData` 동작이 유지됩니다.
- 호출 시 쿼리 옵션은 액션에서 다룹니다. `.load()`는 선언한 쿼리 인자만 받습니다.
- 단일, 무한, 실시간 쿼리 필드 모두 셀렉터 API를 제공합니다.

<a id="existing-actions-remain-valid"></a>

## 기존 액션도 그대로 동작합니다

`.query()`를 제거하거나 의미를 바꾸지 않습니다.

```ts
await this.model.products.query({ page, filter })
await this.model.products.refetch()
this.model.products.set(serverData)
```

마운트된 화면이 요청을 소유하면 셀렉터 `.load()`를 사용하세요. 사용자 명령, 미리 불러오기, 강제 요청, 여러 쿼리 조정, 부수 효과에는 액션 메서드를 유지합니다. 기존 `useEffect` 방식도 호환됩니다.

새 React 훅은 없습니다. `useModel()`과 `create()`가 반환하는 훅의 셀렉터에 기능이 추가됐습니다.

<a id="server-suspense-guidance"></a>

## 서버 Suspense 안내

문서에 캐시를 고려하는 App Router 폴백 패턴을 추가했습니다. 클라이언트 폴백은 이미 성공한 활성 쿼리를 수동으로 표시하거나 스켈레톤을 보여 줍니다. 완료된 서버 분기는 `silent(() => resource.set(data))`로 리소스를 초기화합니다.

기존 쿼리 상태와 서버 초기화를 사용하므로 별도 hydration API가 필요하지 않습니다.
