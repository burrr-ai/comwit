<a id="durable-data-without-changing-the-model-api"></a>

## 모델 API를 바꾸지 않고 데이터를 저장합니다

v2.2.0은 로컬 우선 리소스를 베타에서 안정 버전으로 올립니다. `local()`은 IndexedDB 기반의 독립 모델 필드를 만들고, `local.query()`와 `local.infinite()`는 같은 저장 기반 위에 원격 로딩과 재검증을 선택적으로 더합니다.

```ts
const products = local.collection<Product>({
  key: 'products',
  version: 1,
  scope: ({ state }) => {
    const userId = state(userModel).me?.id
    return userId ? `user:${userId}` : null
  },
})

const productModel = model({
  detail: local<Product | null, { id: string }>({
    source: products,
    initialData: null,
  }),
  list: local.query<Product[], ProductFilter>({
    source: products,
    initialData: [],
    staleTime: 30_000,
    queryFn: api.product.list,
  }),
})
```

독립 리소스는 클라이언트 요청을 시작하지 않고 저장된 정확한 뷰를 복원하거나 서버 렌더링 데이터를 받아 초기화합니다. 쿼리 기반 리소스는 먼저 복원하고 일반 `staleTime` 규칙에 따라 최신 요청을 건너뛰거나 오래된 데이터를 백그라운드에서 재검증합니다.

<a id="normalized-collections"></a>

## 정규화된 컬렉션

컬렉션은 기준 엔티티와 각 리소스/쿼리 인자의 순서 있는 뷰를 분리해 저장합니다. 목록 조각을 완전한 상세 응답으로 취급하지 않으면서 목록과 상세 필드가 갱신을 공유할 수 있습니다.

- 엔티티 ID 기본값은 `entity.id`이며, 다른 필드는 `getId`로 지원합니다.
- `merge`와 `revision`으로 조각 병합을 지정하고 오래된 서버 데이터를 거부합니다.
- 정적 또는 지연 계산되는 컬렉션 스코프로 공개/사용자/테넌트 캐시를 분리합니다.
- 스코프가 바뀌면 이전 메모리 쿼리 캐시를 버리고 사용자 간 응답 반영을 막습니다.
- 로컬 수정은 IndexedDB에 저장되고 같은 엔티티를 공유하는 로드된 뷰에 전파됩니다.

컬렉션 `version`은 명시적인 스키마 경계입니다. 내장 마이그레이션은 없으며 버전을 올리면 해당 스코프와 컬렉션의 이전 뷰를 무효화하고 오래된 행을 정리합니다.

<a id="server-and-failure-behavior"></a>

## 서버와 실패 시 동작

서버에서는 IndexedDB를 건너뜁니다. 독립 리소스는 초기화된 값을 유지하고 쿼리 어댑터는 일반 드라이버를 사용합니다. 브라우저 저장소가 실패해도 모델 접근을 깨뜨리지 않고 메모리 동작으로 전환합니다.

변경 전송함, 오프라인 재시도 큐, CRDT, 기기 간 충돌 해결 엔진은 추가하지 않습니다. 저장된 데이터로 첫 화면과 클라이언트 연속성을 유지하되 동기화의 기준은 서버로 두세요.

<a id="selector-compatibility-fix"></a>

## 셀렉터 호환성 수정

파생, computed, 검증, 히스토리 확장이 동결된 모델 스냅샷을 만들어도 셀렉터 `.load()`가 동작합니다. 불변 스냅샷을 유지하면서 별도 프록시 대상을 사용해 JavaScript Proxy 불변 조건 오류를 피합니다.

## 업그레이드

```bash
yarn add @comwit/state@2.2.0
```
