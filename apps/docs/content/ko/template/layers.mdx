<a id="the-four-layers"></a>

# 네 개의 계층

```text
page  →  state  →  api  →  repository
```

각 계층은 하나의 역할과 한 방향의 의존성을 가집니다. 이 페이지는 템플릿이 설치하는 네 개의 `.ai.md` 가이드를 요약한 것입니다. 전체 예제를 포함한 해당 가이드가 최종 기준입니다.

<a id="repository--the-only-door-to-data"></a>

## Repository — 데이터로 가는 유일한 문

`src/server/repository/{entity}.ts`는 서버 전용이며 애그리거트 루트마다 파일 하나를 둡니다. 정해진 이름으로 원시 테이블 값을 제공하고 모킹 행에서 왔는지 데이터베이스에서 왔는지를 감춥니다.

```ts
import 'server-only'
import { uuid } from './id'

export async function create(data: { title: string }): Promise<Post> {
  const now = new Date()
  const post: Post = {
    id: uuid(),
    title: data.title,
    createdAt: now,
    updatedAt: now,
    deletedAt: null,
  }
  posts.push(post)
  return post
}
```

`_data/`의 모킹 행은 테이블처럼 정규화합니다. 평탄하며 중복이 없고, 외래 키는 ID로 저장하며, `likeCount` 같은 계산 값은 저장하지 않고 조회 시 파생합니다. 데이터베이스를 연결할 때는 함수 본문만 바뀝니다.

<a id="api--server-actions-shaped-for-the-screen"></a>

## API — 화면에 맞춘 서버 액션

`src/services/{service}/api/{domain}/`에 둡니다. 모든 메서드는 `createAction`으로 감싼 `'use server'` 함수이며 `index.ts`에서 `resolveActions`를 통해 객체 하나로 내보냅니다. 빌드는 이 객체를 단일 POST 라우트 핸들러 위의 타입이 지정된 파사드로 교체합니다. Server Component는 매니페스트를 직접 호출하고 브라우저는 메서드별 요청 하나를 보냅니다. 네이티브 Server Actions가 아닌 키트 자체 전송 방식이며 이유는 [설계 결정](/template/docs/decisions)에서 설명합니다.

```ts
// types.ts — the contract, written first
export interface PostAPI {
  /** List query — always Pageable */
  findAll: (filter: FindAllFilter, pageable: PageRequest) => Promise<Pageable<PostSimple>>
  /** Detail query */
  find: (id: string) => Promise<PostDetail>
  /** Create */
  create: (request: CreatePostRequest) => Promise<void>
}
```

```ts
// actions/create.ts
'use server'
import { createAction, ActionError } from '@/lib/utils'

async function _create(request: CreatePostRequest): Promise<void> {
  if (!request.title) throw new ActionError('Enter a title')
  await repository.create(request)
}
export const create = createAction(_create)
```

api 계층이 담당하는 것은 다음과 같습니다.

- **화면에 맞는 응답.** 리포지토리의 `{ likeCount: 3, userId: 'abc' }`가 `{ likeCount: 3, isLikedByMe: true, displayCount: '3개' }`로 바뀝니다. 상대 시간(`30분 전`)과 포맷한 날짜도 공유 `kst` 도우미로 여기서 만들며 컴포넌트에서는 만들지 않습니다.
- **최소한의 인수.** 현재 사용자는 호출자가 전달하지 않고 액션 내부 세션에서 가져옵니다. 공개 리소스가 아니면 쿼리는 사용자가 소유한 것만 반환합니다.
- **사용자에게 보여줄 오류.** `ActionError` 메시지만 브라우저에 도달하며 나머지는 기록한 뒤 가립니다.
- **데이터베이스에 직접 접근하지 않기.** 모킹이든 실제 데이터든 리포지토리를 거칩니다.

<a id="state--the-domain-model-and-every-side-effect"></a>

## State — 도메인 모델과 모든 부수 효과

`src/services/{service}/state/{domain}/`은 `@comwit/state`를 가져오는 유일한 위치입니다. 네 가지 파일을 순서대로 작성합니다.

```text
types.ts      State + Actions types — read this and you know the domain
model.ts      model() with queries and local fields
actions/*.ts  load · crud · interact — every side effect lives here
index.ts      create() the hook, re-export types
```

```ts
// model.ts
export const product = model<ProductState>({
  products: query<Pageable<Product>, { page: number }>({
    initialData: { items: [], total: 0, page: 1, limit: 20, totalPages: 0 },
    queryFn: ({ page }) => api.product.findAll({}, { page, limit: 20 }),
    placeholderData: keepPreviousData,
  }),
  stats: query<ProductStats>({ initialData: EMPTY_STATS, queryFn: () => api.product.getStats() }),
  selectedIds: [],
})
```

```ts
// actions/crud.ts
export const crudActions = action<Pick<ProductActions, 'delete'>>(({ state }) => {
  class CrudActions {
    private model = state(product)

    @OnError((e: unknown) => toast.error(e instanceof Error ? e.message : 'Something went wrong'))
    async delete(id: string) {
      if (!(await popup.confirm({ title: 'Delete this item?', destructive: true }))) return
      const snapshot = [...this.model.products.data.items]
      this.model.products.data.items = snapshot.filter((p) => p.id !== id) // optimistic
      try {
        await api.product.delete(id)
        await Promise.all([this.model.products.refetch(), this.model.stats.refetch()])
      } catch {
        this.model.products.data.items = snapshot // rollback
        throw new Error('Failed to delete')
      }
    }
  }
  return new CrudActions()
})
```

가이드가 요구하는 규칙은 다음과 같습니다.

- **목록, 상세, 통계를 함께.** 변경은 액션 하나에서 모두 갱신하고 영향을 준 데이터를 다시 가져옵니다.
- **부수 효과는 액션 안에만.** 토스트, 확인 창, `context.router` 내비게이션, `state(otherModel)`을 통한 다른 도메인 읽기가 해당합니다. 컴포넌트는 액션 하나만 호출합니다.
- **최초 로드는 선택자가 소유.** 선택자 안의 `state.products.load({ page })`가 커밋 후 요청을 시작하고 키 기준으로 중복을 제거합니다. `useEffect` 초기화는 하지 않습니다.
- **서버 소유 데이터는 하이드레이션.** Server Component가 값을 준비하고 작은 클라이언트 어댑터가 `useDomain.hydrate(...)`를 호출하면 소비자는 로딩 없이 읽습니다. 기본 인증도 이 경로를 따릅니다. 서비스 레이아웃에서 `getMe()`를 기다려 `user.me`에 하이드레이션합니다.
- **액션 컬렉션은 통째로.** `actions: state.actions`를 선택하세요. 프록시에서 메서드 하나만 떼면 런타임 오류가 발생할 수 있습니다.
- **반복 작업에는 데코레이터.** `@OnError`, `@OnSuccess`, `@Authorized`, `@Debounce`, 그리고 재사용 가능한 `@LoginRequired`를 만드는 `intercept()`를 사용합니다.

<a id="page--sections-that-read-and-render"></a>

## Page — 읽고 렌더링하는 섹션

`src/services/{service}/page/{route}/`에 둡니다. `index.tsx`는 섹션을 조합하며 각 섹션은 자체 파일을 가집니다. 레이아웃의 서버 부분을 제외하면 모두 `'use client'`입니다.

```tsx
'use client'
export function ProductsSection({ page }: { page: number }) {
  const product = useProduct((state) => ({
    products: state.products.load({ page }),
    actions: state.actions,
  }))
  if (product.products.isError) return <ErrorMessage error={product.products.error} />
  if (product.products.isLoading) return <ProductsSkeleton />
  return (
    <>
      {product.products.isFetching && <Spinner />}
      {product.products.data.items.map((p) => (
        <ProductCard key={p.id} product={p} />
      ))}
      <Pagination
        current={product.products.data.page}
        total={product.products.data.totalPages}
        onPageChange={(next) => product.actions.openPage(next)}
      />
    </>
  )
}
```

- **파일마다 도메인 훅 한 번, 네임스페이스 스타일.** `product.products`, `product.actions.openPage()`처럼 사용합니다. 구조 분해하거나 같은 도메인을 두 번 호출하지 않습니다.
- **데이터 처리 금지.** `.filter().length`, `.reduce()`, `.slice(0, 3)`를 사용하지 않습니다. 페이지네이션 시 컴포넌트에는 현재 페이지 데이터만 있어 클라이언트 수치는 구조적으로 잘못됩니다. api가 처리합니다.
- **오류, 로딩, 데이터 순서.** `isLoading`은 최초 로드이고 `isFetching`은 데이터가 화면에 남아 있는 백그라운드 갱신입니다.
- **설치된 컴포넌트만.** `Button`, `Input`, `Dialog`, `DataTable` 등은 `src/lib/components/ui`에서 가져옵니다. 원시 `<button>`, `<input>`은 린트 오류입니다. 필요한 것이 없다면 직접 만들기 전에 `pnpm ui add <name>`을 실행하세요.
- **값보다 토큰 먼저.** 색상, 글자, 모서리 반경, 그림자는 `globals.css`의 토큰 계약에서 가져오고 어조는 `design.md`가 결정합니다.

<a id="the-admin-service"></a>

## 관리자 서비스

`admin`도 동일한 네 계층을 사용하며 자체 도메인, 자체 Better Auth 인스턴스, DB 기준 세션을 가집니다. 라우트는 안정적인 내부 `/admin` 경로에 있고 공개 진입점은 `src/proxy.ts`가 다시 쓰는 프로젝트별 접두사입니다. 직접 `/admin/*`을 요청하면 404를 받습니다. 관리자 회원가입은 없습니다. 첫 계정은 명시적 요청이 있을 때만 서버 전용 관리자 API로 만들고 비밀번호 변경은 로그인 뒤에 둡니다.
