# 코딩 에이전트와 작업하기

모델이 이 템플릿에서 제품을 만드는 과정을 지켜보며 구조를 다듬었습니다. 모델에 필요한 모든 것이 저장소에 있습니다. 규칙 파일 하나, 계층별 가이드, 일회성 설정용 스킬, 사람이 보기 전에 잘못된 배치를 거부하는 린트 규칙입니다. Claude Code, Codex, Antigravity는 같은 파일을 읽습니다.

## `AGENTS.md`

규칙 파일입니다. `CLAUDE.md`는 이 파일을 가져오기만 하므로 복사본은 하나입니다. 의존성 흐름, 서비스와 도메인, 스킬, 기술 스택 표, 프로젝트 트리를 다룹니다. 데이터베이스, 저장소, 배포는 설명하지 않습니다. 이는 프로젝트가 결정할 사항이며 리포지토리 계층이 api, state, page 코드에서 분리합니다.

<a id="aimd-beside-every-layer"></a>

## 각 계층 옆의 `.ai.md`

| 가이드                         | 읽어야 하는 시점                                               |
| ------------------------------ | -------------------------------------------------------------- |
| `src/app/.ai.md`               | 라우트, 레이아웃, 인증 경계를 수정하기 전                      |
| `src/services/.ai.md`          | 서비스 아래의 모든 작업 전. import 규칙과 계층 의존성          |
| `src/services/api.ai.md`       | 서버 액션 작성 전                                              |
| `src/services/state.ai.md`     | 모델, 액션, 훅 작성 전                                         |
| `src/services/page.ai.md`      | 화면 작성 전. 설치된 컴포넌트 목록 포함                        |
| `src/services/design.md`       | 모든 시각적 결정 전. 어조, 분위기, 글자 크기 체계, 토큰 사용   |
| `src/services/admin/.ai.md`    | 관리자 라우트, 계정 규칙, 사용자에게 진입 URL을 안내하는 방법  |
| `src/server/repository/.ai.md` | 리포지토리 규칙, CRUD 이름, 메모리 행, 데이터베이스 전환       |
| `.storybook/stories/.ai.md`    | 페이지 스토리 작성/변경 전. 사이드바 구조, api 모킹 경계, 상태 |

구조가 대부분의 의미를 전달하므로 가이드는 짧습니다. 작성 순서, 이름 접미사, 부수 효과의 위치, 이전에 겪은 함정처럼 폴더 트리만으로 표현할 수 없는 몇 가지를 설명합니다.

<a id="skills"></a>

## 스킬

스킬은 `.agents/skills/<name>/`에 있고 Codex와 Antigravity가 직접 읽습니다. `.claude/skills/<name>/`에는 같은 frontmatter를 갖고 원본을 가리키는 스텁이 있습니다. 둘이 달라지면 `pnpm agents:test`가 실패합니다.

**`app-setup`** — 앱 같은 제품을 위한 일회성 설정입니다. 하단 탭, 전체 화면 상세, 방문 기록을 고려한 뒤로 가기 앱 바, 페이지 전환, 뷰포트, PWA 설치 배너를 구성합니다. CLI는 감지된 라우터에 맞게 `comwit-ui`의 셸(`app-shell`, `app-screen`, `bottom-sheet`)을 설치하고 라우트 그룹, 상세 UI, 상세 상태에 관한 가이드 섹션 세 개를 추가합니다. 이후 에이전트가 요청한 탭과 데이터를 연결합니다. 검증 후 스킬은 자신을 제거하고 가이드는 남습니다.

**`auth-setup`** — 하나 이상의 서비스에 Drizzle 기반 Better Auth를 설치합니다. 각 서비스는 접두사가 있는 테이블, 자체 쿠키, 기본 경로, 인증 인스턴스를 가집니다. `app`은 서명된 세션 쿠키 캐시를 사용하며 `admin`은 DB를 기준으로 하고 회원가입이 없습니다. 스킬은 템플릿의 `TODO(auth-setup)` 모킹(`getMe`, 로그인 액션)을 실제 세션 읽기로 대체하고 하이드레이션 경계를 유지합니다. 먼저 연결된 데이터베이스가 필요합니다.

**`seo-optimize`** — 사이트 설정, `buildMetadata`, JSON-LD, sitemap, robots를 포함한 `src/lib/seo`를 설치하고 루트 레이아웃에 연결합니다. 절대 URL은 `SITE_URL`에서 만듭니다.

<a id="storybook-as-the-review-surface"></a>

## 리뷰 화면으로 사용하는 Storybook

`pnpm storybook`은 실제 서비스 레이아웃 안에서 실제 상태와 액션으로 페이지를 렌더링합니다. api 계층의 공개 객체만 `.storybook/mocks/api/{service}-{domain}.ts`의 모킹으로 교체합니다. 모킹 누락이나 서버 import는 앱이 아니라 Storybook 빌드를 실패시킵니다. 스토리는 페이지 단위이며 `.storybook/stories/{service}/` 아래에 페이지별 파일 하나를 둡니다. 페이지의 각 상태는 이름 있는 내보내기로 제공하고 디자인 시스템 개요는 사이드바 맨 위에 둡니다. 에이전트는 페이지를 수정할 때마다 스토리도 작성하거나 갱신합니다. `pnpm validate:storybook`은 `pnpm run validate`와 별도로 Storybook 전용 타입 검사, 린트, 경계 테스트를 실행합니다.

<a id="lint-as-the-last-reader"></a>

## 마지막 검토자로서의 린트

`eslint-rules/`의 규칙은 `pnpm run validate` 때마다 실행됩니다. 아키텍처를 코드로 표현하여 잘못 배치된 파일, 데이터를 포맷하는 컴포넌트, 데이터베이스에 직접 접근하는 api 모듈이 리뷰 전에 실패하게 합니다. 전체 목록은 [폴더 구조](/template/docs/structure#what-enforces-it) 페이지에 있습니다.

<a id="design-guide"></a>

## 디자인 가이드

`src/services/design.md`는 시각적 어조의 단일 기준입니다. 모든 요소에 이유가 있어야 하고, 섹션마다 메시지 하나를 유지하며, 들어갈 분량이 아니라 역할에 따라 글자 크기를 정합니다. 모든 변경을 그것을 만드는 토큰(`--brand`, `--radius-scale`, `--display-font` 등)과 연결하여 컴포넌트 수정은 마지막에 하도록 합니다. 프로젝트가 어조와 분위기를 정하면 화면보다 이 파일을 먼저 바꿉니다.

<a id="what-the-template-leaves-to-you"></a>

## 템플릿이 사용자에게 맡기는 것

- 데이터베이스와 드라이버
- 객체 저장소 버킷
- 호스팅 플랫폼. `pnpm run build`는 표준 Next.js 결과물을 만들며 스캐폴딩 시 `--opennext`를 사용하면 Cloudflare Workers를 연결합니다.
- 브랜드. 색상, 글꼴, 로고는 `globals.css`의 토큰 재정의와 컴포넌트 하나로 구성합니다.
- UI 언어. 기본값은 `src/lib/ui-text.ts`의 한국어이며 이 파일 하나를 번역하면 됩니다.
