# create()

Combines a model and its actions into a React hook.

```ts
import { create } from '@comwit/state'
```

## Usage

```ts
import { create } from '@comwit/state'
import type { PostState, PostActions } from './types'
import { post } from './model'
import { crudActions } from './actions/crud'
import { loadActions } from './actions/load'

export const usePost = create<PostState, PostActions>(post, {
  actions: [crudActions, loadActions],
})
```

## Selector pattern

The returned hook accepts an optional selector:

```tsx
// Select specific fields — only re-renders when these change
const { posts, actions } = usePost((s) => ({
  posts: s.posts,
  actions: s.actions,
}))

// No selector — returns everything (re-renders on any change)
const state = usePost()
```

## Deep equality

Selectors use deep equality comparison. The component only re-renders when the selected values actually change, not on every state mutation.

```tsx
// This only re-renders when posts.data changes, not when
// unrelated state like `current` changes
const { posts } = usePost((s) => ({ posts: s.posts }))
```

## Reading query fields

Call `.load(arg)` in the selector when the mounted component owns a non-suspending request. It
returns loading state immediately and starts the query after commit:

```tsx
const posts = usePost((s) => s.posts.load({ page }))

if (posts.isLoading) return <Skeleton />
if (posts.isError) return <p>Error: {posts.error}</p>
return posts.data.map((post) => <Card key={post.id} post={post} />)
```

Selecting `s.posts` without `.load(...)` only observes existing state; it does not fetch. Existing action-driven loading remains valid for commands and coordinated workflows.

For data fetched by a Server Component, call the generated hook's `hydrate()` method in a small
client route adapter before reading the hook normally:

```tsx
function PostRoute({ slug, initialPost }: Props) {
  usePost.hydrate({ detail: { arg: slug, data: initialPost } })
  return <PostDetail />
}

function PostDetail() {
  const post = usePost((s) => s.detail.data)
  if (!post) return <NotFound />
  return <article>{post.title}</article>
}
```

`hydrate()` returns nothing. A new entry initializes before the following domain-hook read takes its
first snapshot; an observed entry is replaced only after the requesting render commits. Call it
unconditionally like a hook. `null` and `undefined` are safe no-ops.

Selector `.suspend(arg)` is experimental. It starts or reuses `queryFn` during render and accepts no
Promise or initial-data override. Do not use it with a Next.js Server Function; run that function in
a Server Component and use `hydrate()` instead.

## Calling actions

Actions are available on `s.actions`:

```tsx
const { actions } = usePost((s) => ({ actions: s.actions }))

useEffect(() => {
  actions.loadPosts()
}, [])
```

The effect pattern is backward compatible. Prefer selector `.load(...)` when the view owns client
fetching and `hydrate(...)` when a Server Component owns the resolved query value.
