# silent()

Suppresses subscriber notifications during synchronous state mutations.

```ts
import { silent } from '@comwit/state'
```

## Usage

Use `silent()` when a synchronous internal update must not notify React or other model subscribers.
Nested calls keep the outer silent scope active.

```ts
silent(() => {
  model.primary = nextPrimary
  silent(() => {
    model.secondary = nextSecondary
  })
})
```

The callback must be synchronous. An `async` callback cannot remain request-local across `await`
boundaries, so TypeScript rejects Promise-returning callbacks.

## Not for render-time hydration

Do not call an action that mutates a model from a component's render body, even when the action uses
`silent()`. React's `useSyncExternalStore` checks snapshots independently of subscriber
notifications. If the snapshot changes during render, React may discard and retry the uncommitted
tree.

```tsx
// Incorrect
function PostInit({ initialPost }: { initialPost: Post }) {
  const actions = usePost((state) => state.actions)
  actions.init(initialPost)
  return null
}
```

Use [`useHydrate()`](/docs/api/hydrate) to schedule server-provided state after React commits:

```tsx
function PostInit({ initialPost }: { initialPost: Post }) {
  const actions = usePost((state) => state.actions)
  useHydrate(() => actions.init(initialPost), [initialPost, actions])
  return null
}
```

The hydration action should perform ordinary mutations without `silent()`. This lets mounted
consumers observe the committed update.

## How it works

`silent(fn)` increments a synchronous scope depth while `fn` runs. Model mutations still happen,
but subscriber callbacks are skipped until the outermost scope exits. Snapshot versions still
change, which is why `silent()` cannot make render-time external-store mutations safe.
