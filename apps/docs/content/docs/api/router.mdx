# URL search parameters

`useSearchParam()` connects one model field to one URL query parameter. The Provider owns the
binding; a `RouterAdapter` supplies navigation without coupling the model to Next.js or another
framework. Available in `@comwit/state@2.4.0-beta.0`.

## Provider setup

```tsx
'use client'

import { ComwitProvider, createBrowserRouterAdapter } from '@comwit/state'
import { useState, type ReactNode } from 'react'

export function Providers({ children }: { children: ReactNode }) {
  const [router] = useState(() => createBrowserRouterAdapter())
  return <ComwitProvider router={router}>{children}</ComwitProvider>
}
```

The browser adapter uses native `pushState` and `replaceState`, observes external calls to those
methods, and listens for back/forward and hash navigation. Subscriptions install only after a
binding commits and are removed when its last observer unmounts. Notifications run outside
React's commit phase.

Next App Router supports this native history path and updates `usePathname()` and
`useSearchParams()` with it. It is suitable for client UI state such as the selected thread or tab;
it does not request a new Server Component payload. There is no Next import, peer dependency, or
separate Next adapter. See [Next's native history documentation](https://nextjs.org/docs/app/getting-started/linking-and-navigating#native-history-api).

Keep the adapter stable for the Provider's lifetime. To replace it, remount the Provider with a
different React `key`.

## Bind a model field

```tsx
import { model, useSearchParam } from '@comwit/state'

export const threadModel = model({
  requestedThreadId: null as string | null,
  activeThreadId: null as string | null,
})

function ThreadRoute() {
  const thread = useSearchParam(threadModel, 'requestedThreadId', {
    key: 'thread',
    defaultValue: null,
    history: 'push',
  })

  if (!thread.ready) return <div>Loading selection…</div>
  return <button onClick={() => thread.set('thread-2')}>Open thread 2</button>
}
```

Mount one binding per field and query key in each Provider. Other components can read the model
normally. Duplicate active bindings throw instead of competing over the URL.

The initial render and server HTML use a passive snapshot with `ready: false`. After commit, the
binding applies the URL to the model **before enabling state-to-URL writes**. A missing parameter
applies `defaultValue`; it does not automatically rewrite the URL. Gate initialization and
selection work on `ready`. Do not call `set()` or mutate model state during render.

After initialization, ordinary actions updating the bound model field write its value to the URL.
Writes are coalesced in a microtask. An external navigation changing the owned parameter or
pathname cancels obsolete pending writes. Unrelated query parameters, repeated query values, and
the fragment are preserved. Back/forward applies the URL to the model without creating another
history entry. Serialization may normalize query encoding, such as `%20` to `+`.

## Initial defaults, async results, and project changes

```tsx
const request = thread.getSnapshot()
const threads = await loadThreads(projectId)

// The application also checks its project/request token before using this result.
const selected = threads.find((item) => item.id === request.value)?.id ?? threads[0]?.id ?? null

thread.set(selected, {
  history: 'replace',
  ifRevision: request.revision,
})
```

Sort the list in the application's preferred order before selecting its first item. A valid URL
selection wins; a missing or invalid selection falls back to the newest thread. Use `replace` for
this normalization so Back does not revisit an invalid URL. Each URL navigation or local selection
changes `revision`. `ifRevision` returns `false` when a newer request has superseded the result,
including a URL update the adapter has not notified yet. A canonical no-op `set()` does not change
the revision or write history.

For asynchronous thread switching, keep the requested selection separate from a transient
`activeThreadId`. Loading may clear the active field, and a failed optimistic switch may restore it.
Binding those temporary changes would create unwanted history entries. A successful user switch
can update `requestedThreadId` through an action (default `push`) or call
`thread.set(id, { history: 'push', ifRevision })`. Failed and superseded switches leave it alone.
The application's request tokens/cancellation must also protect the loaded thread data and active
selection; the binding guards only its own field and URL.

When the project changes, key the component containing the binding:

```tsx
<ThreadRoute key={projectId} />
```

The old binding cancels pending writes and its saved `set()` callbacks return `false`. The new
binding reads the new URL before observing the existing model, even if the enclosing Provider and
model are shared. Other Provider state can remain mounted. Also guard list/data responses by
project ID and request token. Independent Providers own independent model state and binding
registrations; adapters observing the same browser window still share that window's URL.

## API

```ts
useSearchParam(model, field, {
  key: 'thread',
  defaultValue: null,
  history: 'push', // default; or 'replace'
})
```

| Result                                  | Meaning                                                                                                                 |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `ready`                                 | The binding has committed and read an available URL                                                                     |
| `value`                                 | The current bound model value                                                                                           |
| `revision`                              | A version for guarding asynchronous work                                                                                |
| `getSnapshot()`                         | Latest processed `{ ready, value, revision }` without subscribing                                                       |
| `set(value, { history?, ifRevision? })` | Change the field and URL immediately; returns `false` before initialization, after cleanup, or for an obsolete revision |

`set` and `getSnapshot` have stable references for a binding's lifetime. The returned object stays
stable until its snapshot changes. Changes to the model, field, key, default, history option, or
codec functions replace the binding, so keep custom codec functions stable with module scope or
`useCallback`. Store `revision` for short-lived async work within that binding, not across mounts.

Strings and nullable strings use the raw parameter value by default. Other types require pure
`parse` and `serialize` functions. `parse` also handles a missing or malformed value; returning
`null` from `serialize` removes the parameter. For example:

```tsx
const parsePage = (raw: string | null) => (/^[1-9]\d*$/.test(raw ?? '') ? Number(raw) : 1)
const serializePage = (value: number) => (value === 1 ? null : String(value))

const page = useSearchParam(paginationModel, 'page', {
  key: 'page',
  defaultValue: 1,
  parse: parsePage,
  serialize: serializePage,
})
```

## Custom routers

```ts
import type { RouterAdapter } from '@comwit/state'

const adapter: RouterAdapter = {
  getSnapshot: () => locationStore.href, // pathname + search + hash, or null until ready
  subscribe: (listener) => locationStore.subscribe(listener),
  navigate(href, { history }) {
    locationStore[history](href)
  },
}
```

`navigate` must synchronously expose the committed URL through `getSnapshot`. Subscribers must
observe external navigation as well as the adapter's own writes and return a cleanup function.
Notify outside React render and insertion effects. A pending asynchronous router method alone
does not satisfy this contract; for Next query-only client state, use the supplied browser adapter.
