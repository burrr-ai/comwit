# URL search parameters

`useSearchParam()` connects one model field to a URL query parameter. Use the existing global
`ComwitProvider`; browser reads, writes, and history subscriptions are handled internally.
Available in `@comwit/state@2.4.0-beta.3`.

## Setup

```tsx
'use client'
import { ComwitProvider } from '@comwit/state'

export function Providers({ children, router }) {
  return <ComwitProvider context={{ router }}>{children}</ComwitProvider>
}
```

Your existing `context.router` remains available to application actions. Only mounted search
parameter bindings subscribe to browser navigation. Ordinary `useModel()` calls do not read the
URL, install history listeners, or invoke framework hooks.

```tsx
import { model, useModel, useSearchParam } from '@comwit/state'

const locationModel = model({ requestedThreadId: null as string | null })

function ThreadPage() {
  const thread = useSearchParam(locationModel, 'requestedThreadId', {
    key: 'thread',
    defaultValue: null,
    // history defaults to 'replace'
  })
  const selected = useModel(locationModel, (state) => state.requestedThreadId)

  if (!thread.ready) return <div>Loading selection…</div>
  return <button onClick={() => thread.set('thread-2')}>{selected}</button>
}
```

Mount one binding per model field and query key in each Provider. Other components can read the
model normally. Keep a small URL selection model when the active session field changes temporarily
while data is loading. Place the binding before that model's first selector read; unrelated models
can be read earlier. An action factory may capture the selection model's proxy before the binding:
its identity is preserved.

## Optional server initialization

Provide one synchronous request getter when the framework can read search parameters during SSR:

```tsx
<ComwitProvider context={{ router }} getServerSearchParams={getServerSearchParams}>
  {children}
</ComwitProvider>
```

```ts
type GetServerSearchParams = () => string | null
// Example results: '?thread=one', 'thread=one', '', or null when unavailable.
```

The application owns the framework-specific getter. The library calls it during the Provider's
server initialization and never in the browser. The getter should be a pure synchronous read;
React may retry an uncommitted server render. The result is retained for that Provider mount.
An empty string is an available search with no parameters; `null` means unavailable. Supplying this
getter does not itself make a prerendered route request-time rendered.

| Getter result                    | Server and first hydration render    | After client commit                    |
| -------------------------------- | ------------------------------------ | -------------------------------------- |
| Getter absent or returns `null`  | Model default, `ready: false`        | Initialize from the latest browser URL |
| Returns a string, including `''` | URL selection/default, `ready: true` | Reconcile with the latest browser URL  |

When the binding runs before the model's first selector read, both `useSearchParam().value` and
`useModel()` see the server selection in that render. Server-side action reads through an already
captured proxy see the same selection. A model already observed before binding retains its existing
server snapshot and initializes from the browser after commit.

The Provider automatically carries its server search to hydration in an inert JSON element with a
Provider-specific React ID. Script delimiters and Unicode separators are escaped. This is internal
transport: the application supplies only the getter. Keep the Provider's getter prop present on both
server and browser renders; the browser never calls it. As with other React IDs, independent SSR
roots sharing a document should use matching, distinct React `identifierPrefix` options.

The library maintains an immutable server snapshot and applies live browser values after commit.
It does not mutate an observed client store during render; an abandoned binding cannot change its
selected field or start subscriptions. Later Provider renders do not call the getter again or replay
an old server search. A component that first mounts after hydration initializes from the current
browser URL.

If the server rendered thread A and the URL changes to B before hydration, the first hydration
snapshot still matches A. Commit applies B and cancels obsolete write-back. Hash and unrelated query
differences leave the selected value and revision unchanged. An effect that starts asynchronous
work should check that its render is still current:

```tsx
useEffect(() => {
  const current = thread.getSnapshot()
  if (!current.ready || current.revision !== thread.revision) return
  // Load current.value with the application's project/request cancellation guards.
}, [thread.ready, thread.value, thread.revision, thread.getSnapshot])
```

This initializes URL selection state. Message data, query results, and streams still follow the
application's data-loading flow; keep their loading UI until those results are ready.

## History and navigation

Actions changing the bound model field and `thread.set()` replace the current history entry by
default. Switching threads therefore does not grow browser history. Opt into history entries for
all selections with `history: 'push'` on the binding, or override one call:

```tsx
thread.set('thread-2', { history: 'push' })
thread.set('canonical-thread', { history: 'replace' })
```

A per-call override does not change the binding's configured mode. A canonical no-op does not
write history or increment the revision. Ordinary model writes are coalesced in a microtask;
`set()` updates immediately after commit.

The internal browser integration observes native `pushState`/`replaceState`, back/forward, and hash
navigation. Incoming navigation updates the model without an echo. Writes preserve unrelated query
parameters, repeated unrelated values, and the hash. Query encoding may normalize, such as `%20`
to `+`. URL changes affecting the owned parameter or pathname cancel stale pending writes.
Subscriptions and queued writes are cleaned up when the binding unmounts.

Next App Router integrates the native History API with its location hooks. This is appropriate for
client selection state; it does not request new Server Component data. The library has no Next
imports or framework hook calls. See [Next's native history documentation](https://nextjs.org/docs/app/getting-started/linking-and-navigating#native-history-api).

## Async defaults and project changes

```tsx
const request = thread.getSnapshot()
const threads = await loadThreads(projectId)
// Also verify the application's project/request token before using this result.
const selected = threads.find((item) => item.id === request.value)?.id ?? threads[0]?.id ?? null
thread.set(selected, { history: 'replace', ifRevision: request.revision })
```

A valid URL selection wins. Sort the list in the preferred order and use the first item to normalize
a missing or invalid selection. `ifRevision` rejects obsolete results, including a browser URL update
whose notification is still pending. Revision changes follow the selected value or pathname;
unrelated query/hash changes and acknowledgements of the same selection do not increment it.

Use a separate requested-selection field if `activeThreadId` is cleared during loading or rolled
back after a failure. Successful user choices can write the bound field; failed and superseded
requests should leave it alone. Guard message/session updates by project and request token as well:
the binding only guards its own field and URL.

Key the component containing the binding by project ID when its lifecycle should restart. Keep the
single global Provider mounted. The old binding cancels pending writes and saved `set()` callbacks
return `false`; the new binding reads the current browser URL before observing model writes.

## API

```ts
useSearchParam(model, field, {
  key: 'thread',
  defaultValue: null,
  history: 'replace', // default; 'push' opts into history entries
})
```

| Result                                  | Meaning                                                                                                 |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `ready`                                 | A server snapshot or committed browser URL supplies a selection                                         |
| `value`                                 | The selected model value for this snapshot                                                              |
| `revision`                              | Version for guarding asynchronous work                                                                  |
| `getSnapshot()`                         | Latest processed `{ ready, value, revision }` without subscribing                                       |
| `set(value, { history?, ifRevision? })` | Returns `false` before commit, after cleanup, while the URL is unavailable, or for an obsolete revision |

`set` and `getSnapshot` references stay stable for a binding's lifetime. The returned object changes
only when its snapshot changes. Model/field/key/default/history/codec changes replace the binding;
keep custom codec functions stable with module scope or `useCallback`. Do not call `set()` or mutate
state during render.

Strings and nullable strings use the raw parameter by default. Other types require pure `parse`
and `serialize` functions. The parser handles missing or malformed values; returning `null` from
the serializer removes the parameter. The codec must produce the same value on server and client.

```tsx
const parsePage = (raw: string | null) => (/^[1-9]\d*$/.test(raw ?? '') ? Number(raw) : 1)
const serializePage = (value: number) => (value === 1 ? null : String(value))
const page = useSearchParam(paginationModel, 'page', {
  key: 'page',
  defaultValue: 1,
  parse: parsePage,
  serialize: serializePage,
})
```
