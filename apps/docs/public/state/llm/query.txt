# comwit — Query System Reference

> Full API reference for selector `.load()` / `.suspend()`, imperative query methods,
> `query.infinite()`, `query.realtime()`, caching, and resource state.

For IndexedDB-backed normalized list/detail/infinite views, see
https://library.comwit.io/state/llm/local.txt. `local.query()` and `local.infinite()` preserve every
corresponding query method below; standalone `local()` has no network driver.

## query(opts)

Creates a single data-fetching resource descriptor. Used inside `model()`.

```ts
import { model, query } from '@comwit/state'

export const post = model<PostState>({
  posts: query<Post[]>({
    initialData: [],
    queryFn: () => api.post.findAll(),
  }),
  comments: query<Comment[], string>({
    initialData: [],
    queryFn: (postId) => api.comment.findAll(postId),
  }),
})
```

### Options

| Option            | Type                                        | Description                                                                                        |
| ----------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `initialData`     | `TData`                                     | **Required.** Initial value before any fetch.                                                      |
| `queryFn`         | `(arg, context) => TData \| Promise<TData>` | **Required.** Fetcher function.                                                                    |
| `suspense`        | `boolean`                                   | **Deprecated.** Choose `.suspend(arg)` in the selector instead.                                    |
| `staleTime`       | `number`                                    | Milliseconds before cached data is considered stale. Default `0`.                                  |
| `gcTime`          | `number`                                    | Milliseconds a cache entry survives after the model loses its last observer. Default `5 * 60_000`. |
| `placeholderData` | `TData \| (arg, previousData) => TData`     | Data shown while fetching. Use `keepPreviousData` helper.                                          |

### queryFn Signature

```ts
queryFn: (arg: TArg, context: { state: Readonly<ResourceSingleState<TData>> }) =>
  TData | Promise<TData>
```

- `arg` — the argument passed to `.query(arg)`. Type is the second generic: `Query<TData, TArg>`.
- `context.state` — a readonly snapshot of the current resource state (includes `data`, `isLoading`, etc.).

The return value can be:

- Plain data (`TData`) — assigned to `.data`
- An object with `data` key plus optional state overrides

## query.infinite(opts)

Creates an infinite/paginated resource descriptor. Use with `Query.Infinite<T>` type.

```ts
import { model, query } from '@comwit/state'

export const feed = model<FeedState>({
  trending: query.infinite<Post[]>({
    initialData: [],
    queryFn: (_, { state }) => api.post.trending(state.cursor),
  }),
})
```

### queryFn Return Shape (Infinite)

`queryFn` for `query.infinite()` must return an object with `data`, and optionally `cursor` and `hasMore`:

```ts
queryFn: async (_, { state }) => {
  const res = await api.post.trending(state.cursor)
  return { data: res.items, cursor: res.nextCursor, hasMore: res.hasNext }
}
```

Without `hasMore: true` in the response, `nextFetch()` becomes a no-op.

## query.realtime(opts)

Creates a real-time resource descriptor that combines initial data fetching with live subscription updates. After `queryFn` succeeds, the `subscribe` function is called with callbacks to push live updates.

```ts
import { model, query } from '@comwit/state'

const roomId = 'general'

export const chat = model<ChatState>({
  messages: query.realtime<Message[]>({
    initialData: [],
    queryFn: () => api.chat.history(roomId),
    subscribe: (callbacks) => {
      const ws = new WebSocket(`/ws/chat/${roomId}`)
      ws.onmessage = (e) => {
        callbacks.update((prev) => [...prev, JSON.parse(e.data)])
      }
      ws.onopen = () => callbacks.onStatus('connected')
      ws.onclose = () => callbacks.onStatus('disconnected')
      ws.onerror = (e) => callbacks.onError(e)
      return () => ws.close()
    },
  }),
})
```

### Options

| Option        | Type                                        | Description                                                        |
| ------------- | ------------------------------------------- | ------------------------------------------------------------------ |
| `initialData` | `TData`                                     | **Required.** Initial value before any fetch.                      |
| `queryFn`     | `(arg, context) => TData \| Promise<TData>` | **Required.** Initial data fetcher.                                |
| `subscribe`   | `(callbacks) => () => void`                 | **Required.** Sets up live subscription. Returns cleanup function. |

### Subscribe Callbacks

| Callback   | Signature                                   | Description                        |
| ---------- | ------------------------------------------- | ---------------------------------- |
| `update`   | `(updater: (prev: TData) => TData) => void` | Merge data using updater function. |
| `set`      | `(data: TData) => void`                     | Replace data entirely.             |
| `refetch`  | `() => void`                                | Re-execute the queryFn.            |
| `onStatus` | `(status: ConnectionStatus) => void`        | Update connection status.          |
| `onError`  | `(error: unknown) => void`                  | Set error state.                   |

### ConnectionStatus

`'connecting' | 'connected' | 'disconnected' | 'reconnecting'`

### Methods

- `.query(arg?)` — Fetches initial data and starts subscription.
- `.refetch()` — Re-fetches data (re-subscribes after success).
- `.set(data)` — Manually set data.
- `.unsubscribe()` — Stops the live subscription. Sets `connectionStatus` to `'disconnected'`.

### Realtime-only Flags

| Flag               | Type               | Description                          |
| ------------------ | ------------------ | ------------------------------------ |
| `connectionStatus` | `ConnectionStatus` | Current connection state.            |
| `isConnected`      | `boolean`          | `true` when status is `'connected'`. |

### Type

```ts
import { Query } from '@comwit/state'

messages: Query.Realtime<Message[]>
messages: Query.Realtime<Message[], string> // with argument
```

## Types

```ts
import { Query } from '@comwit/state'

// Single query
posts: Query<Post[]>

// Single query with argument
comments: Query<Comment[], string>

// Infinite query
trending: Query.Infinite<Post[]>

// Realtime query
messages: Query.Realtime<Message[]>

// Legacy Suspense variants — deprecated; use Query<T> plus selector .suspend()
posts: Query.Suspense<Post[]>
trending: Query.SuspenseInfinite<Post[]>
```

## Experimental Suspense Support

Choose Suspense where the query is consumed:

```tsx
function PostList() {
  const posts = usePost((state) => state.posts.suspend())
  return posts.data.map((post) => <Card key={post.id} post={post} />)
}

;<Suspense fallback={<Skeleton />}>
  <PostList />
</Suspense>
```

Use experimental `.suspend(arg)` when a `<Suspense>` fallback should handle initial loading.
Keep the boundary inside `ComwitProvider` and add an error boundary for initial query failures.
Later refetches keep successful data visible; use `isFetching` for a refresh indicator.
Use `.load(arg)` when the component should render its own loading and error states.

### Next.js SSR setup

Pass `useServerInsertedHTML` to the provider to reuse server results without a second browser
request (available in the `2.5.0` beta line):

```tsx
'use client'

import { ComwitProvider } from '@comwit/state'
import { useServerInsertedHTML } from 'next/navigation'

<ComwitProvider useServerInsertedHTML={useServerInsertedHTML}>{children}</ComwitProvider>
```

- Keep the `<Suspense>` boundary inside this provider.
- Write `queryFn` to work on both server and browser. Use a Route Handler or external API with an
  absolute URL for server-side `fetch`; return JSON-serializable data.
- Use `hydrate()` when fetching requires database code or Next.js Server Functions: await the data
  in a Server Component, then call `useDomain.hydrate({ field: { arg, data } })` in a client route
  adapter before reading the domain hook.
- A server-side failure shows the fallback; the browser retries the request.
- Without `useServerInsertedHTML`, the browser fetches again during hydration. This SSR setup
  supports React 19 streaming SSR with the Next.js App Router, not `renderToString` or the Pages Router.

Use `.suspend(arg)` in new code instead of the deprecated `{ suspense: true }` option and
`Query.Suspense*` types.

## Methods

React selectors and actions intentionally expose different loading controls.

### .load(arg?) — React selectors

Call `.load()` only inside a `useModel()` selector or a hook created by `create()`:

```tsx
const posts = usePost((state) => state.posts.load())
const comments = usePost((state) => state.comments.load(postId))
```

- The argument is inferred from `Query<TData, TArg>`; an argument query requires exactly that type, while `Query<TData>` uses `.load()`.
- Calling `.load(arg)` opts the selector into automatic loading. Merely selecting `state.posts` is passive and never fetches.
- The selector returns the normal resource state (`data`, flags, error, plus infinite/realtime fields).
- Render loading UI from `isLoading`, which is available on the first render.
- Pass the route ID or filter as the argument. Changing it loads the matching data; unrelated rerenders do not restart the request.
- Concurrent selector loads for the same resource and key are deduplicated.
- Call-time options are deliberately unavailable. Configure provider/query defaults, or use an action method below for forced or coordinated requests.

Selector loading is additive. Existing `useEffect(() => actions.load(), [])` and event-driven actions continue to work.

### .suspend(arg?) — React selectors

Call `.suspend()` only inside a selector:

```tsx
const post = usePost((state) => state.post.suspend(postId))
```

- Pass only the query argument, not a Promise or initial data.
- Put the component inside `<Suspense>` under `ComwitProvider` to show a fallback while loading.
- Add an error boundary for initial query failures.
- Later refetches keep successful data visible; show a refresh indicator with `isFetching`.
- If `enabled` or `dependsOn` blocks execution, the selector returns the current initial state.
- For SSR, `queryFn` must work on server and browser. Use the Next.js setup above to reuse server
  results without a second browser request.
- Supports value- or Promise-returning single/infinite queries, including `local.query()` and
  `local.infinite()`. Realtime queries and async-iterable fetchers are not supported.

Use `.load(arg)` instead when the component should render `isLoading` and `isError` itself.

### .query(arg?, options?)

Imperative action method. Triggers the fetch. An entry activated by `.query()`, selector `.load()`,
`.set()`, or `.hydrate()` can be refetched; `.nextFetch()` also requires `hasMore: true`.

```ts
// No argument
await this.model.posts.query()

// With argument
await this.model.comments.query(postId)

// With options
await this.model.posts.query({ force: true })

// With argument and options
await this.model.comments.query(postId, { staleTime: 60_000 })
```

**Options:**

- `force: boolean` — Bypass cache staleness check and always fetch.
- `staleTime`, `gcTime`, `placeholderData` — Override defaults per call.

### .refetch()

Re-fetches using the active/last argument. No-op until an entry has been loaded, set, or hydrated.

```ts
await this.model.posts.refetch()
```

### .set(data, options?)

Manually set resource data without fetching. Marks the resource as successful.

```ts
// Set just the data
this.model.posts.set([newPost, ...this.model.posts.data])

// Set data + state overrides
this.model.posts.set({ data: [], isSuccess: true })

// Initialize an exact local/server-owned detail view
this.model.detail.set(product, { arg: { id: product.id } })
```

The optional `arg` establishes the exact resource identity. It is primarily useful when a server
initializer sets a standalone local resource before a fallback has activated that route key.

### .nextFetch(arg?)

**Infinite queries only.** Fetches the next page. Appends results to existing data. No-op when `hasMore` is `false`.

```ts
await this.model.trending.nextFetch()
```

### .previousFetch(arg?, options?)

**Infinite queries only.** Navigates back through cursor history. Restores the previous cursor state.

```ts
await this.model.trending.previousFetch()
```

## State Flags

| Flag         | Type             | Description                                             |
| ------------ | ---------------- | ------------------------------------------------------- |
| `data`       | `TData`          | The fetched data (or `initialData` before first fetch). |
| `isLoading`  | `boolean`        | `true` during the initial fetch (before first success). |
| `isFetching` | `boolean`        | `true` during any fetch (including refetches).          |
| `isSuccess`  | `boolean`        | `true` after at least one successful fetch.             |
| `isError`    | `boolean`        | `true` when the last fetch failed.                      |
| `error`      | `string \| null` | Error message from the last failed fetch.               |

### Infinite-only flags

| Flag      | Type             | Description                                                              |
| --------- | ---------------- | ------------------------------------------------------------------------ |
| `cursor`  | `string \| null` | Current pagination cursor.                                               |
| `hasMore` | `boolean`        | Whether more pages are available. `nextFetch()` is a no-op when `false`. |

## Reuse data between requests

- Set `staleTime` to reuse fresh results without fetching again; default `0` considers data stale
  immediately. Use `.refetch()` for an explicit refresh.
- Set `gcTime` to control how long unused results are kept after the model loses its last observer;
  default `5 * 60_000` (five minutes).
- Pass the same argument to reuse its cached data. Switching arguments restores matching cached
  data when available.
- Set `placeholderData` for an argument that has no cached data. Use `keepPreviousData` below to
  keep the previous result visible while fetching.
- One query field displays one active argument at a time. Use separate fields when two views need
  different arguments simultaneously.

## keepPreviousData

Helper for `placeholderData` that keeps the previous data while fetching new data:

```ts
import { keepPreviousData, ComwitProvider } from '@comwit/state'

<ComwitProvider
  defaultOptions={{
    query: {
      placeholderData: keepPreviousData,
    },
  }}
>
```

Or per-query:

```ts
query<Post[]>({
  initialData: [],
  placeholderData: keepPreviousData,
  queryFn: () => api.post.findAll(),
})
```

## Full Example

```ts
// types.ts
import { Query } from '@comwit/state'

export type FeedState = {
  posts: Query<Post[]>
  trending: Query.Infinite<Post[]>
  postById: Query<Post | null, string>
}

// model.ts
import { model, query } from '@comwit/state'

export const feed = model<FeedState>({
  posts: query<Post[]>({
    initialData: [],
    staleTime: 30_000,
    queryFn: () => api.post.findAll(),
  }),
  trending: query.infinite<Post[]>({
    initialData: [],
    queryFn: async (_, { state }) => {
      const res = await api.post.trending(state.cursor)
      return { data: res.items, cursor: res.nextCursor, hasMore: res.hasNext }
    },
  }),
  postById: query<Post | null, string>({
    initialData: null,
    queryFn: (id) => api.post.findById(id),
  }),
})

// actions/load.ts
import { action } from '@comwit/state'

export const feedLoader = action<Pick<FeedActions, 'loadPosts' | 'loadMore' | 'loadPost'>>(({ state }) => {
  class FeedLoader {
    private model = state(feed)

    async loadPosts() {
      await this.model.posts.query()
    }

    async loadMore() {
      await this.model.trending.nextFetch()
    }

    async loadPost(id: string) {
      await this.model.postById.query(id)
    }
  }
  return new FeedLoader()
})

// usage in component
const posts = useFeed((s) => s.posts.load())
const trending = useFeed((s) => s.trending.load())

if (posts.isLoading) return <Skeleton />
if (posts.isError) return <p>Error: {posts.error}</p>
```

## Next.js server rendering

Two paths. Either is valid; pick per route.

Path 1 — `hydrate()`: await the server function in a Server Component and hydrate the resolved entry
in a small client route adapter:

```tsx
function ProductRoute({ id, initialDetail }: Props) {
  useProduct.hydrate({ detail: { arg: { id }, data: initialDetail } })
  return <ProductDetail />
}

function ProductDetail() {
  const detail = useProduct((state) => state.detail.data)
  return detail ? <ProductView product={detail} /> : <NotFound />
}
```

Call `hydrate()` unconditionally in the route adapter before reading the domain hook. Read data
through the hook in the UI; `hydrate()` uses the supplied value without calling `queryFn`. Do not
initialize the same store by invoking a mutating action during render.

Path 2 — `.suspend(arg)` (experimental): fetch where the component reads the data. Put the
component inside `<Suspense>` under `ComwitProvider` to show a loading fallback:

```tsx
// Server Component
<Suspense fallback={<ProductSkeleton />}>
  <ProductDetail id={id} />
</Suspense>

// Client Component — experimental; needs useServerInsertedHTML on the provider.
function ProductDetail({ id }: { id: string }) {
  const detail = useProduct((state) => state.detail.suspend({ id }))
  return detail.data ? <ProductView product={detail.data} /> : <NotFound />
}
```

Use `.suspend()` when `queryFn` can run on both server and browser. Use `hydrate()` for database
reads or Next.js Server Functions. Pass `useServerInsertedHTML` to the provider to reuse server
results without a second browser request (see "Next.js SSR setup" above).

## Slow initial loading

Set `slowLoadingMs` on a query when a skeleton should appear only for a slow initial load. Read
`isSlowLoading` alongside `isLoading`; the option does not delay the request or its result.

```ts
const projects = model({
  list: local.query<Project[]>({
    source: projectRows,
    initialData: [],
    queryFn: () => api.project.list(),
    slowLoadingMs: 500,
  }),
})
```

```tsx
const projects = useProjects((state) => state.list.load())
if (projects.isLoading && !projects.isSuccess) {
  return projects.isSlowLoading ? <ProjectsSkeleton /> : null
}
if (projects.isSuccess) return <ProjectsList items={projects.data} />
if (projects.isError) return <LoadError error={projects.error} />
return null
```

`isSlowLoading: false` does **not** mean the data is ready. A successful empty result is ready;
inspect status rather than data truthiness. Success takes precedence over background errors for
local queries. Layout space and whether to show a skeleton remain application decisions.

- Set the option on `query()`, `query.infinite()`, `query.realtime()`, `local.query()`, or
  `local.infinite()`. It is not a provider default or a per-call option, and standalone `local()`
  and `persist()` do not support it. Without the option, `isSlowLoading` stays false.
- Use finite milliseconds from `0` through `2147483647`; invalid values throw `RangeError`.
  Use `0` for an immediate indicator or, for example, `500` to wait at least 500ms.
- Use this flag with `.load()` or action-driven browser requests. For `.suspend()`, use the
  `<Suspense>` fallback. During SSR and initial hydration, the flag is false.
- The flag covers initial loading, including local restoration followed by a network request.
  It becomes false as soon as data is usable or loading ends. Background refetches do not set it.
- Changing the query argument or local scope starts a new loading interval. Components reading
  the same query share the flag; do not add a separate timer per component.
- The flag has no minimum display duration. If the UI needs one, handle it in the component.
